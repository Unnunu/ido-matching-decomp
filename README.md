# IDO matching decomp

Matching decompilation of the IRIX Development Option (IDO) compiler
toolchain. The goal is to rebuild the original programs as C, Pascal and
assembly sources that produce byte-identical objects with the original IDO
compilers.

The highest priority is the set of programs needed to compile a C file to an
unlinked object:

- `cc` - compiler driver, runs the other tools as needed
- `cfe` - C frontend, preprocessor and driver for optimisation/code generation
- `uopt` - optimiser used by `-O2`
- `ugen` - code generator used at lower optimisation levels
- `as1` - assembler for compiler-generated assembly

Lower priority but also of interest:

- `as0` - assembler for handwritten assembly
- `ld` - linker for producing linked object files
- `uld` (ucode linker) and `umerge` (procedure merger) for `-O3`
- `upas` - Pascal frontend

`cc`, `cfe` and `as0` are written in C; `cfe` also contains Yacc components.
`uopt`, `ugen`, `as1`, `uld`, `umerge` and `upas` are written in Pascal.

| 7.1 | 995 / 3627 | 33.20% | 34.86% | 0.72% |

| **all** | **1019 / 5407** | **21.63%** | **20.45%** | **0.45%** |

Percentages are matched byte percentages. Library code that is statically

tracked in separate buckets instead of inflating program progress. See
[docs/DIFFING.md](docs/DIFFING.md) for the accounting rules.

## Requirements

- Linux x86_64 is the tested platform. The Makefile also detects macOS, but CI
  only covers Linux; macOS requires a working `mips-linux-gnu` binutils
  toolchain and the macOS IDO recomp release.
- `git`, `make`, `gcc`, `curl` and `tar`.
- `uv` with Python 3.13. The repository pins Python in `.python-version`.
- MIPS binutils with the `mips-linux-gnu-` prefix: `ld`, `as`, `objcopy`,
  `objdump`, `readelf` and `nm`.
- `gcc-multilib` (the host syntax check uses `-m32`).
- `objdiff-cli` 3.8.3 or newer for diffing and progress checks. The objdiff GUI
  is optional.
- Network access for the IDO recomp release download, Python dependencies and
  the objdiff release.

On Debian or Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y build-essential git curl binutils-mips-linux-gnu gcc-multilib
```

Install `uv` if it is not already available:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.13
```

Install `objdiff-cli` (Linux x86_64):

```bash
mkdir -p "$HOME/.local/bin"
curl -fsSL https://github.com/encounter/objdiff/releases/download/v3.8.3/objdiff-cli-linux-x86_64 \
  -o "$HOME/.local/bin/objdiff-cli"
chmod +x "$HOME/.local/bin/objdiff-cli"
export PATH="$HOME/.local/bin:$PATH"
objdiff-cli --version
```

On other platforms, download the matching asset from the
[objdiff releases page](https://github.com/encounter/objdiff/releases). If the
binary is not on `PATH`, pass it explicitly with
`OBJDIFF_CLI=/path/to/objdiff-cli`.

## Setup

```bash
git clone https://github.com/Unnunu/ido-matching-decomp.git
cd ido-matching-decomp
uv sync
make setup
make disasm
make
```

`make setup` installs the Python environment, downloads the IDO recomp release
into `tools/ido_recomp/` and builds `tools/yacc/yacc`. `make disasm`
disassembles the original binaries from `ido/<version>/` into `asm/<version>/`.
`make` then builds the current version into `build/src/<version>/`.

The original IDO binaries under `ido/` and the split definitions under
`symbols/` are tracked, so no external IDO installation is needed.

For both supported versions:

```bash
make disasm-all
make both
```

## Building

```bash
make                  # current VERSION, default 7.1
make VERSION=5.3      # IDO 5.3
make both             # 5.3 and 7.1 without cleaning
make disasm           # disassemble current VERSION
make disasm-all       # disassemble 5.3 and 7.1
make clean            # remove build/ and generated Yacc C files
make distclean        # also remove asm/, tools/ido_recomp and tools/yacc/yacc
```

The supported values of `VERSION` are `7.1` and `5.3`. Builds use the
recompiled IDO compilers in `tools/ido_recomp/`, assemble target objects with
`mips-linux-gnu-as`, and run a host `gcc` syntax check before each C file is
compiled.

Bare `make` also refreshes untracked progress artifacts when `objdiff.json` and
`build/report.json` already exist. It never rewrites the tracked `PROGRESS.md`;
use `make match`, `make progress` or `make baseline` for that.

## Diffing

`make diff` rebuilds stale objects, regenerates the objdiff configuration, and
runs the diff:

```bash
make diff UNIT=7.1/ugen/build SYM=build_tree
```

`objdiff-cli diff` itself does not build, so build and generate the config first
when calling it directly:

```bash
make both
make objdiff
objdiff-cli diff -p . -u 7.1/ugen/build build_tree
```

For non-interactive output:

```bash
make diff UNIT=7.1/ugen/build SYM=build_tree DIFF_FLAGS='-o /tmp/diff.json'
```

To use the GUI, open the repository root in objdiff. The **Build** button and
the on-save watcher rebuild the selected unit's base object automatically
(`build_base` and `custom_make` are generated into `objdiff.json`). Unit names
follow `<version>/<program>/<file>`, for example `7.1/ugen/build`. Library
units use `<version>/<library>/<module>/<program>/<target>`, for example
`7.1/libu/uini/ugen/ugen_04F430`.

Base objects are also given the target's local symbol names for anonymous
data and functions (`RO_STR_...`, `D_...`, `func_...`) so objdiff can compare
individual strings and data items instead of one raw section blob.

See [docs/DIFFING.md](docs/DIFFING.md) for symbol mappings, library units and
all available options.

## Progress and matching

A full progress pass covers both versions, so disassemble and build both first:

```bash
make disasm-all
make both
```

Then use the progress targets:

```bash
make match      # incremental update; writes PROGRESS.md and build/progress.json
make progress   # full pass, prints the table
make check      # fail on stale PROGRESS.md or a regression vs build/baseline.json
make baseline   # explicitly refresh the regression baseline
```

The objdiff report (`build/report.json`) is the source of truth. A function
counts as matched only when objdiff reports a 100% fuzzy match. Target objects
without a built base object are still counted in the denominator as unmatched,
so unstarted source files cannot disappear from progress.

The tools exclude `__start`, `_mcount`, `_ftext`, `_rld_*`, crt/runtime symbols
and `*.NON_MATCHING` aliases. `NON_MATCHING` markers are derived from objdiff
results; the generated view is written to `build/asm-marked/<version>/<program>/`
without rewriting `asm/`.

Per-program overrides live in `symbols/<version>/<program>.match_overrides.txt`:

```text
# target_symbol = matched | ignored
func_00401234 = matched
func_00405678 = ignored
```

`matched` seeds a target-to-base mapping; `ignored` removes the symbol from both
the numerator and the denominator. Files that do not exist are treated as
empty.

`PROGRESS.md` is tracked. `build/progress.json`, `build/report.json` and
`build/baseline.json` are untracked build artifacts. The baseline is created on
the first `make match` or `make progress` run; later runs do not refresh it
unless you run `make baseline`.

## Version support

"Builds" means the version has a disassembly target and can be compiled with
`make VERSION=<version>` or `make both`. Matching status for every program is
in [PROGRESS.md](PROGRESS.md).

| Program | 5.3 builds | 7.1 builds | Description |
| --- | --- | --- | --- |
| `cc` | yes | yes | compiler driver |
| `cfe` | yes | yes | C frontend |
| `ugen` | yes | yes | code generator |
| `as0` | yes | yes | assembler for handwritten assembly |
| `as1` | no | yes | assembler for compiler-generated assembly |
| `uopt` | no | yes | `-O2` optimiser |
| `umerge` | no | yes | procedure merger for `-O3` |
| `ld`, `uld`, `upas`, `ujoin`, `usplit`, `acpp`, `copt` | no | no | not yet wired into the build |

## Repository layout

- `src/` - C and Pascal sources, organised by program plus `libu`, `libp` and
  `mld` library sources.
- `asm/<version>/<program>/` - generated disassembly, ignored by git.
- `build/` - compiled base objects, assembled target objects, reports and
  progress data, ignored by git.
- `symbols/<version>/` - tracked split definitions (`*.splits.csv`), library
  membership (`libraries.csv`) and optional `*.match_overrides.txt`.
- `context/` - generated spimdisasm context CSVs, ignored by git.
- `include/` - project headers, including IRIX/IDO headers under `include/indy/`.
- `ido/` - original IDO binaries used for disassembly.
- `lib/indy/dev/usr/lib/` - tracked crt objects from the IDO release.
- `tools/` - build helpers: `gen_objdiff.py`, `objdiff_make.py`,
  `symbolize_base.py`, `progress.py`, `library.py` and the bundled `yacc/`.
- `docs/DIFFING.md` - detailed objdiff and progress documentation.
- `PROGRESS.md` - generated, tracked matching status.
- `Makefile` - build, disassembly, diff and progress entry points.

Development task and session notes are maintained outside this repository and
are not part of the project.

## Troubleshooting

### `Please install or build mips-linux-gnu`

The Makefile checks for `mips-linux-gnu-ld` before doing anything. Install the
binutils package:

```bash
sudo apt-get install -y binutils-mips-linux-gnu
```

If the tools are installed with a different prefix, override it:

```bash
make MIPS_BINUTILS_PREFIX=/path/to/mips-linux-gnu- VERSION=7.1
```

### IDO recomp download fails

`make setup` downloads the pinned `v1.2` release with `curl` and `tar`. Check
network access and any proxy settings, then retry from a clean directory:

```bash
rm -rf tools/ido_recomp
make setup
```

The download target is `tools/ido_recomp/<version>/`; `make distclean` removes
the whole tree if you want a full reset.

### `uv` or Python version problems

The project requires Python 3.13. Check `uv --version`, then:

```bash
uv python install 3.13
uv sync
```

`uv sync` uses `pyproject.toml`, `uv.lock` and `.python-version`; do not install
the Python packages with a system `pip`.

### `objdiff-cli: command not found`

Diffing, `make match`, `make progress` and `make check` need `objdiff-cli`
3.8.3 or newer. Install it as shown above, add it to `PATH`, or point the
Makefile at it:

```bash
make check OBJDIFF_CLI=/path/to/objdiff-cli
make diff UNIT=7.1/ugen/build SYM=build_tree OBJDIFF_CLI=/path/to/objdiff-cli
```

`make` and `make both` do not require objdiff.

### Stale `asm/` after symbol or split changes

`asm/`, `build/` and `objdiff.json` are ignored, so files from an older checkout
can survive a source update. Regenerate everything:

```bash
rm -rf asm build objdiff.json
make setup
make disasm-all
make -j "$(nproc)" both
make objdiff
```

To regenerate only one program:

```bash
rm -rf asm/7.1/ugen
make VERSION=7.1 disasm
make VERSION=7.1
```

Stale target files can change progress numbers; CI always starts from a clean
checkout, so reproduce CI locally with the full clean sequence above.

## CI

Two GitHub Actions workflows run on every push and pull request:

- `.github/workflows/ci.yml` installs the build dependencies and `uv`,
  caches `tools/ido_recomp` and `build/baseline.json`, downloads objdiff-cli
  3.8.3, then runs `uv sync`, `make setup`, `make disasm-all`,
  `make -j "$(nproc)" both` and `make check`. It bootstraps a baseline when the
  cache is empty. Pushes to `main` refresh and save the baseline. Pull requests
  can add the `skip-progress` label to skip the progress regression check.
  Reports, progress JSON, baseline and `PROGRESS.md` are uploaded as artifacts.
- `.github/workflows/warnings_checks.yml` runs a syntax-only warning build for
  both versions with `WERROR=1` and `CC="@:"`, so it does not need the IDO
  recompiler.

Reproduce the main CI sequence locally:

```bash
uv sync
make setup
make disasm-all
make -j "$(nproc)" both
make check
```

Reproduce the warning checks:

```bash
make yacc MIPS_BINUTILS_PREFIX=
for version in 7.1 5.3; do
  make -j "$(nproc)" WERROR=1 VERSION="$version" CC="@:" MIPS_BINUTILS_PREFIX=
done
```
